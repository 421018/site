## How the protocol is developed {#development}

The software, the documentation, the tools and this site are open source. Development follows a few simple practices:

- Proposals and discussions happen in public repositories.
- No change goes in without another person reviewing it.
- Each new version is tested on the testnet first.
- The protocol stays current with the technology it is built on.
- Each version publishes its change notes.

[Where to check it →](/get-started/sources)
:::

## Ways to contribute {#ways}

You can join without asking permission. These are the usual ways:

- **Report a problem.** If you find an error, describe it in the public repository.
- **Propose a change.** If you know how to fix or improve something, send your proposal.
- **Review changes.** You can read and comment on other people's proposals.
- **Answer questions.** Help others in the repository's discussion space.

Vulnerabilities are not reported in public. [Report a vulnerability](/open-source/security#report)

## How a change reaches the chain {#changes}

A code proposal does not change the chain by itself. The path is this:

1. Other people review the proposal in the repository.
2. If it is accepted, it goes into a new version of the software.
3. The version is tested on the testnet.
4. It is submitted as a governance proposal on the mainnet.
5. If it is approved, the nodes change version together.

## Technical questions {#questions}

Questions about the protocol, the network, an integration or this site are asked in the public repository's discussion space. It is open to anyone.

The space is only for technical topics. Services are neither offered nor hired there.

Before asking, look at the [frequently asked questions](site:/faq) and the [documentation](/).

## Licenses for contributions {#licenses}
